# Установка 3x-ui на новый VPS

[English version](README.md)

Эта инструкция рассчитана на **компьютер с Linux** и **новый VPS с Ubuntu 24.04**. Вы входите на VPS по SSH как `root` с паролем. Затем создаёте пользователя `ops` и устанавливаете 3x-ui со своего компьютера.

Выполняйте каждую команду там, где указано перед блоком команд. Ansible — программа, которая запускает шаги установки через SSH. Не записывайте пароль или приватный ключ в `.env`.

```text
Компьютер Linux → вход root → создание ops → проверка ops → установка 3x-ui → проверка клиента
```

## Что подготовить

Вам нужны IP-адрес VPS, пароль `root` и домен, который указывает на этот IP-адрес. В примерах используется SSH-порт `22`; если у провайдера другой порт, замените его в SSH-командах. Сохраните доступ к консоли восстановления у провайдера на случай потери SSH.

Откройте терминал **на компьютере с Linux** в папке с этим README. Если на компьютере Ubuntu или Debian, установите программы:

```sh
sudo apt update
sudo apt install -y ansible-core openssh-client python3 nano curl
```

Для другого дистрибутива Linux установите те же программы его менеджером пакетов. Проверьте, что терминал открыт в папке репозитория:

```sh
ls bin/vps.py
```

Команда должна показать `bin/vps.py`. Также выполните `python3 --version`. Нужна версия 3.10 или новее.

## 1. Создайте SSH-ключ на компьютере с Linux

SSH-ключ состоит из двух файлов. Файл с окончанием `.pub` — **публичный ключ**. Его содержимое вы перенесёте на VPS. Второй файл — **приватный ключ**. Он остаётся на вашем компьютере.

```sh
mkdir -p "$HOME/.ssh"
chmod 700 "$HOME/.ssh"
ssh-keygen -t ed25519 -a 100 -f "$HOME/.ssh/standalone_3x_ui_ed25519"
```

Придумайте парольную фразу, введите её и подтвердите. Если `ssh-keygen` сообщает, что файл существует, ответьте **no**. Используйте его, только если это ваш ключ и рядом есть файл `.pub`. Иначе выберите другое имя **во всех следующих командах** и в `.env`.

Покажите публичный ключ и оставьте этот терминал открытым:

```sh
cat "$HOME/.ssh/standalone_3x_ui_ed25519.pub"
```

Скопируйте всю строку, которая начинается с `ssh-ed25519`. Приватный ключ не копируйте.

## 2. Заполните `.env` на компьютере с Linux

`.env` — файл настроек этого VPS. Репозиторий не добавляет ваш настоящий `.env` в Git. Если файл уже существует, `cp -n` сохранит его.

```sh
cp -n .env.ru.example .env
nano .env
```

Сначала измените эти значения:

| Параметр | Что указать |
| --- | --- |
| `DOMAIN` | Ваш домен, например `vpn.example.com`. Его DNS-запись должна указывать на IP VPS. |
| `VPS_HOST` | IP-адрес VPS. |
| `PANEL_ALLOWED_CIDRS` | Внешний IPv4-адрес вашего компьютера и `/32`, например `203.0.113.5/32`. |
| `ACME_EMAIL` | Ваш адрес почты. Поле можно оставить пустым. |

Команда `curl -4 https://api.ipify.org` на вашем компьютере покажет текущий внешний IPv4-адрес. Запишите его в `PANEL_ALLOWED_CIDRS`. Если адрес позже изменится, правило доступа к панели придётся обновить.

В примере текущий SSH-порт — `22`, новый SSH-порт — `2322`, панель — `39089`, подписка — `38443`, VLESS — `443`. Hysteria2 использует UDP-порт `443`, когда указано `ENABLE_HYSTERIA=yes`. Если Hysteria2 не нужна, задайте `ENABLE_HYSTERIA=no`. Если хотите оставить SSH на порту `22`, задайте **оба** значения: `CHANGE_SSH_PORT=no` и `SSH_TARGET_PORT=22`. Остальные порты оставьте разными, как в примере.

Сохраните `.env` в `nano`: нажмите **Ctrl+O**, **Enter**, затем **Ctrl+X**. В `Ctrl+O` используется буква O.

## 3. Войдите на VPS как root и создайте ops

Откройте **второй терминал на компьютере с Linux**. Вместо `YOUR_VPS_IP` подставьте адрес из `VPS_HOST`:

```sh
ssh -p 22 root@YOUR_VPS_IP
```

Если SSH покажет отпечаток нового сервера, сравните его с отпечатком от провайдера перед вводом `yes`. Введите пароль `root`. Теперь вы находитесь **на VPS**.

Проверьте операционную систему:

```sh
cat /etc/os-release
```

Продолжайте, только если там указана Ubuntu 24.04. Выполните **на VPS**:

```sh
adduser --disabled-password --gecos '' ops
usermod -aG sudo ops
install -d -m 0700 -o ops -g ops /home/ops/.ssh
nano /home/ops/.ssh/authorized_keys
```

Если на VPS нет `nano`, выполните `apt-get update` и `apt-get install -y nano`. Затем снова откройте файл. Вставьте **одну строку публичного ключа** из шага 1. Не добавляйте вторую строку. Нажмите **Ctrl+O**, **Enter**, затем **Ctrl+X**.

Оставаясь **на VPS**, задайте права и проверьте число строк:

```sh
chown ops:ops /home/ops/.ssh/authorized_keys
chmod 0600 /home/ops/.ssh/authorized_keys
wc -l /home/ops/.ssh/authorized_keys
```

Последняя команда должна вывести `1` перед именем файла. Теперь разрешите `ops` выполнять `sudo` без пароля:

```sh
VISUAL=nano EDITOR=nano visudo -f /etc/sudoers.d/90-standalone-ops
```

Введите в `nano` ровно одну строку:

```text
ops ALL=(ALL:ALL) NOPASSWD:ALL
```

Нажмите **Ctrl+O**, **Enter**, затем **Ctrl+X**. Если `visudo` покажет ошибку, исправьте строку. Затем выполните **на VPS**:

```sh
chown root:root /etc/sudoers.d/90-standalone-ops
chmod 0440 /etc/sudoers.d/90-standalone-ops
visudo -cf /etc/sudoers.d/90-standalone-ops
```

Последняя команда должна сообщить, что файл проверен. Оставьте соединение `root` открытым до следующего шага.

## 4. Проверьте нового пользователя

Откройте **третий терминал на компьютере с Linux**. Подключитесь по текущему SSH-порту. Пока это `22`:

```sh
ssh -i "$HOME/.ssh/standalone_3x_ui_ed25519" -p 22 ops@YOUR_VPS_IP
```

После входа выполните **на VPS**:

```sh
sudo -n true
exit
```

Команда `sudo -n true` должна завершиться без ошибки и запроса пароля. Если она не работает, исправьте ключ, права или файл sudoers в открытом сеансе `root`. После успешной проверки выполните `exit` и в сеансе `root`.

## 5. Установите 3x-ui с компьютера Linux

Вернитесь в **первый терминал** с открытой папкой репозитория. Загрузите ключ в SSH-агент. Агент позволит установщику использовать ключ с парольной фразой:

```sh
eval "$(ssh-agent -s)"
ssh-add "$HOME/.ssh/standalone_3x_ui_ed25519"
```

Перед установкой разрешите эти порты в **фаерволе провайдера**, если он есть:

| Порт | Кому нужен доступ |
| --- | --- |
| `22/tcp` | Вашему компьютеру во время настройки. Оставьте его до проверки нового SSH-порта. |
| `2322/tcp` | Вашему компьютеру после смены SSH-порта. |
| `80/tcp` | Интернету для выпуска сертификата. |
| `443/tcp` | Клиентам VLESS. |
| `38443/tcp` | Клиентам для подписки. |
| `443/udp` | Клиентам Hysteria2, только если она включена. |
| `39089/tcp` | Только вашему адресу администратора для панели. |

Если вы изменили порты в `.env`, используйте свои числа. Установщик настраивает фаервол на VPS. Фаервол провайдера он не меняет. После проверки SSH на `2322` удалите правило `22/tcp` у провайдера, если меняли порт.

Запускайте команды **на компьютере с Linux** по одной:

1. Покажите настройки и проверьте порты:

   ```sh
   python3 bin/vps.py plan
   ```

2. Проверьте доступ и будущие правила фаервола. Эта команда не меняет VPS:

   ```sh
   python3 bin/vps.py check-network
   ```

3. Установите 3x-ui. Эта команда меняет VPS и переносит SSH на выбранный порт:

   ```sh
   python3 bin/vps.py deploy --apply
   ```

4. Проверьте службы и порты после установки:

   ```sh
   python3 bin/vps.py verify
   ```

## 6. Откройте панель и проверьте клиента

После установки SSH работает на порту `SSH_TARGET_PORT`. Для настроек из примера выполните **на компьютере с Linux**:

```sh
ssh -i "$HOME/.ssh/standalone_3x_ui_ed25519" -p 2322 ops@YOUR_VPS_IP
```

После входа прочитайте данные **на VPS**:

```sh
sudo cat /etc/x-ui/install-result.env
```

В файле указаны данные для входа и путь панели. Домен и порт панели возьмите из `.env`. Не передавайте данные для входа другим людям. Откройте панель с IP-адреса из `PANEL_ALLOWED_CIDRS`. Подписка — адрес, по которому клиент получает свои настройки подключения.

Входящее соединение — настройка протокола и порта для клиентов.

1. Найдите в панели входящее соединение VLESS/TLS. Если включена Hysteria2, найдите и её соединение.
2. Создайте по одному пробному клиенту для каждого включённого соединения. Передайте ссылки на устройство вне сети VPS.
3. Подключитесь с этого устройства и проверьте передачу данных. Откройте адрес подписки и обновите её.
4. После проверки удалите пробных клиентов.

Установщик проверяет службы и порты. Только проверка с внешнего устройства доказывает, что настоящий клиент подключается.

## Если команда остановилась

Не повторяйте `deploy --apply` без проверки состояния VPS. Часть этапов могла завершиться. Проверьте SSH на последнем рабочем порту. Если доступ есть, выполните `python3 bin/vps.py verify`. Если SSH не работает, откройте консоль восстановления провайдера.

Версия панели закреплена в `X_UI_VERSION` и плейбуке установки. Для новой версии нужен отдельный проверенный выпуск репозитория. Этот VPS сможет стать основным узлом для других серверов позднее. Сейчас установка меняет только этот VPS.

Если провайдер запретил SSH-вход `root`, используйте отдельную [инструкцию для консоли провайдера](docs/bootstrap-console.ru.md). Для Windows есть [команды создания ключа](docs/ssh-keys-windows.ru.md). Установщик запускайте в Linux или WSL.

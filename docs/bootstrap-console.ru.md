# Первоначальная настройка через консоль провайдера

[English version](bootstrap-console.md) · [Русский README](../README.ru.md)

Используйте этот вариант, если консоль провайдера позволяет войти как `root`, а вход `root` по паролю через SSH запрещён. Оставьте консоль открытой, пока отдельное подключение пользователя `ops` по ключу и команда `sudo -n true` не заработают. Ниже используется имя `ops`; если в `.env` задан другой `OPS_USER`, подставьте его во все команды.

## 1. Подготовьте локальный ключ и проверьте SSH-ключ сервера

Сначала создайте ключ **на своём компьютере** по отдельной инструкции: [Linux/WSL](ssh-keys-linux.ru.md) или [Windows PowerShell](ssh-keys-windows.ru.md). Там есть точные команды для показа публичного ключа `.pub`. Подготовьте эту **одну строку публичного ключа** для шага 2. Приватный ключ на VPS не переносите. Если подходящий ключ уже есть, укажите его путь в `.env` через `SSH_KEY_PATH` и покажите содержимое соответствующего файла `.pub`.

В консоли провайдера узнайте отпечаток SSH-ключа VPS:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

В Linux/WSL замените `YOUR_VPS_IP` на адрес VPS, а `22` — на его **текущий** SSH-порт; затем проверьте отпечаток полученного ключа сервера:

```sh
VPS_HOST=YOUR_VPS_IP
SSH_PORT=22
ssh-keyscan -p "$SSH_PORT" -t ed25519 "$VPS_HOST" > /tmp/vps-hostkey.pub
ssh-keygen -lf /tmp/vps-hostkey.pub
```

Только при совпадении отпечатка с консолью провайдера проверьте, нет ли старой записи: `ssh-keygen -F "$VPS_HOST"` (для нестандартного порта — `ssh-keygen -F "[$VPS_HOST]:$SSH_PORT"`). Если обнаружили несовпадение, сначала разберитесь с ним. Затем добавьте проверенный ключ в локальный `known_hosts`:

```sh
mkdir -p "$HOME/.ssh"
chmod 700 "$HOME/.ssh"
cat /tmp/vps-hostkey.pub >> "$HOME/.ssh/known_hosts"
chmod 600 "$HOME/.ssh/known_hosts"
```

Пользователи Windows PowerShell могут сверить отпечаток при первом SSH-подключении по [инструкции для Windows](ssh-keys-windows.ru.md).

## 2. Создайте пользователя в консоли VPS

Войдя как `root`, выполните:

```sh
adduser --disabled-password --gecos '' ops
usermod -aG sudo ops
install -d -m 0700 -o ops -g ops /home/ops/.ssh
```

Если на сервере нет `nano`, установите его из консоли `root` командами `apt-get update` и `apt-get install -y nano`. Откройте файл для публичного ключа:

```sh
nano /home/ops/.ssh/authorized_keys
```

Вставьте **всю строку публичного ключа** со своего компьютера, начинающуюся с `ssh-ed25519`. Это должна быть одна строка. В `nano` нажмите **Ctrl+O** (буква O, «записать файл»), затем **Enter** для подтверждения имени файла и **Ctrl+X** для выхода. Подсказки `^O` и `^X` внизу экрана означают Ctrl+O и Ctrl+X. Установите права и убедитесь, что в файле одна строка:

```sh
chown ops:ops /home/ops/.ssh/authorized_keys
chmod 0600 /home/ops/.ssh/authorized_keys
wc -l /home/ops/.ssh/authorized_keys
```

Последняя команда должна показать `1` перед именем файла. Теперь откройте отдельный файл правил sudo через `visudo`, явно выбрав редактор `nano`:

```sh
VISUAL=nano EDITOR=nano visudo -f /etc/sudoers.d/90-standalone-ops
```

Введите **ровно одну строку** (если имя пользователя другое, замените `ops` и здесь):

```text
ops ALL=(ALL:ALL) NOPASSWD:ALL
```

Нажмите **Ctrl+O**, **Enter**, затем **Ctrl+X**. При выходе `visudo` проверит синтаксис; если появится ошибка, вернитесь в редактор и исправьте её, не подтверждая неверный файл. Затем выполните:

```sh
chown root:root /etc/sudoers.d/90-standalone-ops
chmod 0440 /etc/sudoers.d/90-standalone-ops
visudo -cf /etc/sudoers.d/90-standalone-ops
```

Последняя команда должна сообщить, что файл успешно разобран. Если обычная вставка в консоль провайдера не работает, используйте её кнопку вставки/буфера обмена либо аккуратно напечатайте строку публичного ключа. Приватный ключ не вставляйте.

## 3. Проверьте новый доступ до изменения SSH

Из **нового терминала своего компьютера** подключитесь как `ops` по приватному ключу через `BOOTSTRAP_SSH_PORT` и выполните `sudo -n true`. Пример для PowerShell есть в [инструкции для Windows](ssh-keys-windows.ru.md). Для Linux/WSL замените примерные IP и порт в команде `ssh -i "$HOME/.ssh/standalone_3x_ui_ed25519" -p 22 ops@YOUR_VPS_IP`, затем после входа выполните `sudo -n true`. Не закрывайте консоль `root` до успешной проверки. Если вход не работает, проверьте строку ключа, владельцев, права, настройки SSH, синтаксис sudoers и фаервол провайдера через консоль.

Для команды `python3 bin/vps.py verify-access` временно установите в `.env` `CHANGE_SSH_PORT=no` и оба SSH-порта равными текущему. После проверки верните планируемые значения. Продолжайте командами `python3 bin/vps.py check-network` и `python3 bin/vps.py deploy --apply`. После успешной ручной настройки не запускайте повторно автоматический bootstrap через `root`.

Пароль `root`, приватный ключ и учётные данные панели не записывайте в отслеживаемые файлы или переписку.

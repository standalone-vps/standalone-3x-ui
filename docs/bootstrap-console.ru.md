# Первоначальная настройка через консоль провайдера

[English version](bootstrap-console.md) · [Русский README](../README.ru.md)

Используйте этот вариант, если консоль провайдера позволяет войти как `root`, а вход `root` по паролю через SSH запрещён. Оставьте консоль открытой, пока отдельное подключение пользователя `ops` по ключу и команда `sudo -n true` не заработают. Ниже используется имя `ops`; если в `.env` задан другой `OPS_USER`, подставьте его во все команды.

## 1. Подготовьте локальный ключ и проверьте SSH-ключ сервера

На управляющем компьютере при необходимости запустите `python3 bin/vps.py keygen`. Команда создаёт приватный ключ по пути `SSH_KEY_PATH` и публичный ключ рядом с суффиксом `.pub`. Для пути из примера показать **только публичный** ключ можно командой `cat ~/.ssh/standalone_3x_ui_ed25519.pub`. Приватный ключ на VPS не переносите.

В консоли провайдера узнайте отпечаток SSH-ключа VPS: `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`. На управляющем компьютере получите его публичную часть командой `ssh-keyscan -p <текущий-ssh-порт> -t ed25519 <адрес-vps> > /tmp/vps-hostkey.pub` и проверьте отпечаток командой `ssh-keygen -lf /tmp/vps-hostkey.pub`. Добавляйте полученный ключ в `~/.ssh/known_hosts` **только после совпадения отпечатков** (например, `cat /tmp/vps-hostkey.pub >> ~/.ssh/known_hosts`, предварительно проверив, нет ли старой записи). Сам ключ публичный, но без такой сверки нельзя доверять ответу сети. Для нестандартного порта сохраните формат `[host]:port`, который выводит `ssh-keyscan`.

## 2. Создайте пользователя в консоли VPS

Войдя как `root`, выполните:

```sh
adduser --disabled-password --gecos '' ops
usermod -aG sudo ops
install -d -m 0700 -o ops -g ops /home/ops/.ssh
```

Через редактор в консоли поместите одну строку локального файла `.pub` в `/home/ops/.ssh/authorized_keys`. Затем установите владельца и права:

```sh
chown ops:ops /home/ops/.ssh/authorized_keys
chmod 0600 /home/ops/.ssh/authorized_keys
```

Через `visudo -f /etc/sudoers.d/90-standalone-ops` создайте файл с единственной строкой `ops ALL=(ALL:ALL) NOPASSWD:ALL`. Установите владельца `root:root` и режим `0440`, затем проверьте файл: `visudo -cf /etc/sudoers.d/90-standalone-ops`.

## 3. Проверьте новый доступ до изменения SSH

Из **нового терминала** управляющего компьютера подключитесь как `ops` по приватному ключу через `BOOTSTRAP_SSH_PORT` и выполните `sudo -n true`. Не закрывайте консоль `root` до успешной проверки. Если вход не работает, проверьте строку ключа, владельцев, права, настройки SSH, синтаксис sudoers и фаервол провайдера через консоль.

Для команды `python3 bin/vps.py verify-access` временно установите в `.env` `CHANGE_SSH_PORT=no` и оба SSH-порта равными текущему. После проверки верните планируемые значения. Продолжайте командами `python3 bin/vps.py check-network` и `python3 bin/vps.py deploy --apply`. После успешной ручной настройки не запускайте повторно автоматический bootstrap через `root`.

Пароль `root`, приватный ключ и учётные данные панели не записывайте в отслеживаемые файлы или переписку.
